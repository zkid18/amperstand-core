If [`amperstand-tg-bot`](/examples/telegram-bot) and [`amperstand-extension`](/examples/browser-extension) are too much code to read for what you're building (a one-off n8n flow, a phone app, an agent tool), here are the minimum-viable clients in two languages.

## What every client does

Three responsibilities:

1. **Hold the user's server URL + API key** — env var, config screen, settings file
2. **POST captures to the server** — when the user does something
3. **Optionally query back** — list, search, fetch — to give the user feedback

No extraction, no markdown generation, no SQLite. The server does all that.

## Minimal Python client

```python
import httpx, os

class Vault:
    def __init__(self, base_url: str, api_key: str) -> None:
        self.client = httpx.Client(
            base_url=base_url,
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=120,
        )

    def capture(self, url: str) -> dict:
        return self.client.post("/capture", json={"url": url}).json()

    def search(self, q: str, limit: int = 10) -> list[dict]:
        r = self.client.post(
            "/vault/search/hybrid",
            json={"q": q, "limit": limit, "rerank": True},
        )
        return r.json()["items"]

# Usage
vault = Vault(os.environ["AMPERSTAND_BASE_URL"], os.environ["AMPERSTAND_API_KEY"])
doc = vault.capture("https://danluu.com/why-hardware-development-is-hard/")
print(doc["id"], doc["title"])
```

The Telegram bot's [`VaultClient`](/examples/telegram-bot#the-http-client-worth-copying) is essentially this, made async and with a few more endpoints.

## Minimal JS client

```js
class Vault {
  constructor(baseUrl, apiKey) {
    this.baseUrl = baseUrl.replace(/\/$/, "");
    this.headers = {
      "Authorization": `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    };
  }

  async capture(url, { html = null, title = null } = {}) {
    const endpoint = html ? "/capture/html/async" : "/capture/async";
    const body = { url, ...(html && { html, title }) };
    const r = await fetch(`${this.baseUrl}${endpoint}`, {
      method: "POST", headers: this.headers, body: JSON.stringify(body),
    });
    return r.json();   // { job_id, status }
  }

  async pollJob(jobId, { intervalMs = 1000 } = {}) {
    while (true) {
      const r = await fetch(`${this.baseUrl}/jobs/${jobId}`, { headers: this.headers });
      const job = await r.json();
      if (job.status === "done" || job.status === "failed") return job;
      await new Promise(r => setTimeout(r, intervalMs));
    }
  }
}
```

The browser extension's [`clip.js`](/examples/browser-extension#the-capture-flow) is this plus a couple of MV3-specific bits (storage, content script).

## Sync vs async

| Use | When |
| --- | --- |
| `POST /capture` (sync) | Your client can wait 5–120s for the result. Server runs the extractor, returns the saved doc. |
| `POST /capture/async` + poll `GET /jobs/{id}` | Your client can't block. Chat popups, browser popups, mobile share sheets. Returns a `job_id` instantly. |

Async also lets you batch — POST 20 URLs, walk away, check the queue later via `GET /jobs?status=done`.

## Conventions to match

- **Auth**: every endpoint except `/health` requires `Authorization: Bearer <key>`. Don't hardcode; read from env/config.
- **IDs**: doc IDs are 26-char ULIDs. Sortable, URL-safe, no integers.
- **Idempotency**: `/capture` dedups on source URL via `body_hash`. Re-sending the same URL returns the existing doc.
- **Errors**: 4xx = caller fix. 5xx = server tried and failed. Don't auto-retry 4xx.

## Things you don't have to handle

- Extraction (trafilatura, Anysite for LinkedIn/YouTube/Reddit and walled pages, fxtwitter rewrite — server picks based on URL shape)
- Deduplication (`body_hash`-based, server-side)
- Embeddings (capture-time, if server has `OPENAI_API_KEY`)
- File storage (markdown lives at `$AMPERSTAND_DATA_DIR` on the server)

All of that is server-side. Your client just calls HTTP and renders responses.
